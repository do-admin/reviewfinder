# Root Cause Analysis and Fix Plan for IMPROVEMENT-TASKS.md

## Architecture Overview

Content is generated by `scripts/06-generate-website.ts` which uses an AI model to fill a template (`src/data/_template/websites.json`) to produce `src/data/nicezeit/websites.json`. The generated JSON is consumed at build time by Astro pages (`src/pages/[lang]/*.astro`) via `src/lib/page-data.ts`. Several bugs trace back to the generation script, several to shared library code (`page-data.ts`, `global-schema.ts`), and some are component-level issues.

---

## Root Cause Classification for Each Task

### GROUP A: Script/Template Root Cause (fix in `06-generate-website.ts` or `_template/websites.json`)

**Task 1 (Datenschutz wrong data controller)** - **Script root cause**. The generation script copies legal pages "verbatim from the template" (line 1351 of `06-generate-website.ts`). The template's datenschutz blocks contain placeholder text from a previous client ("JAH Verwaltungs GmbH / stadtkueken"). The AI is told "only update company name, address, email, phone" but the template already has specific (wrong) data baked in.

- **Fix**: Update `_template/websites.json` datenschutz blocks to use clearly marked placeholders (e.g. `{LEGAL_NAME}`, `{ADDRESS}`, `{EMAIL}`) instead of real client data. Update the script prompt to instruct the AI to replace these placeholders with the actual business data.

**Task 9 (`[@id]` bug in schema)** - **Script root cause**. The AI model generates `[@id]` instead of `@id` in the JSON. The `schema-org.ts` code handles `@id` correctly (line 120: `if (pub['@id'] != null)`), so the square brackets in the _data_ are the issue.

- **Fix**: Add a post-processing step in `06-generate-website.ts` that finds and replaces `[@id]` with `@id` in all schema objects after AI generation.

**Task 12 (Missing EU ODR link in impressum)** - **Template root cause**. The template's impressum page blocks lack the EU ODR section entirely.

- **Fix**: Add the EU ODR paragraph block to the impressum page in `_template/websites.json`.

**Task 15 (Missing "Eisdiele" keyword)** - **Script root cause / data quality**. The AI-generated titles/H1s/descriptions lack the core business keyword. This is partially a prompt quality issue.

- **Fix**: Enhance the chunk guidelines in `getFillBlanksChunkDefinitions()` for the "Home -- metadata + hero" chunk to explicitly require the primary business keyword in title, H1, and description. However, for the nicezeit data specifically, this is also a data fix in `websites.json`.

**Task 16 (Duplicate H1/subtitle)** - **Script root cause**. AI generates identical text for `hero.h1` and `hero.subtitle`.

- **Fix**: Add explicit instruction in the "metadata + hero" chunk guidelines: "hero.subtitle MUST be different from hero.h1 -- it should communicate a unique value proposition, not repeat the heading."

**Task 17 (Generic FAQ content, cannabis questions)** - **Script root cause / separate FAQ generation**. FAQ data comes from separate JSON files (e.g. `faq.json`), not from the main generation script. The FAQ generation likely uses a generic prompt.

- **Fix**: This is outside `06-generate-website.ts` scope -- needs investigation of FAQ generation scripts. The cannabis content removal and brand-specific FAQ addition are data fixes.

**Task 21 (Missing representative role in impressum)** - **Template root cause**. Template impressum lacks "Inhaber:" prefix before the representative name.

- **Fix**: Update `_template/websites.json` impressum block to include the role label placeholder.

**Task 22 (Umlaut "Ueber Uns")** - **Script root cause**. The AI or template produces ASCII-only text. The generation script's prompt mentions `über Uns` (line 766: `"label": "über Uns"`) but the AI may still generate without umlauts.

- **Fix**: Add a post-processing step that normalizes known German words (Ueber->Über). Also check the header links in `_template/websites.json` for correct umlaut usage.

**Task 34 (Missing must-cover topics)** - **Script/prompt root cause**. Topics from `topics.json` are injected into the prompt but the AI doesn't necessarily cover all of them in the generated content.

- **Fix**: Enhance chunk guidelines for "info + contact" to explicitly require mentioning all topics from `topics.json`.

### GROUP B: Library/Infrastructure Root Cause (fix in `src/lib/`)

**Task 2 (Canonical URLs use wrong domain)** - **`page-data.ts` root cause**. `getPageClientDomain()` (line 379) reads `resolved.clientDomain` which comes from `website.clientDomain ?? topLevelClientDomain` (line 217). Individual websites do NOT have a `clientDomain` field -- only the top-level file has `clientDomain: "nicezeit.com"`. The per-website `deployDomain` field is never used by the code.

- **Fix in `page-data.ts`**: In `getResolvedPageData()`, change line 217 from:
  ```
  clientDomain: website.clientDomain ?? topLevelClientDomain ?? ''
  ```
  to prefer `deployDomain`:
  ```
  clientDomain: website.deployDomain ?? website.clientDomain ?? topLevelClientDomain ?? ''
  ```
  Also add `deployDomain` to the `WebsiteData` interface in `src/types/page.ts`.

**Task 3 (Relative OG/Twitter image URLs)** - **`BaseLayout.astro` + data root cause**. `BaseLayout.astro` outputs `openGraph.images[0].url` and `twitter.images[0]` directly from the data, which are relative paths. The layout never prepends the domain.

- **Fix in `BaseLayout.astro`**: Before rendering, prepend `siteUrl` (already passed as a prop) to relative image URLs. E.g.: `const ogImageUrl = openGraph.images[0].url.startsWith('/') ? siteUrl + openGraph.images[0].url : openGraph.images[0].url`.

**Task 8 (global-schema always reads websites[0])** - **`global-schema.ts` root cause**. `getFirstPage()` hardcodes `websites[0]` (line 14). For multi-site deployments, each site should use its own Organization/WebSite schema.

- **Fix**: Modify `global-schema.ts` to accept a `websiteId` parameter or read from `SITE_ID` env var to select the correct website entry. Change exported functions to accept an optional site index/id.

**Task 13 (Hero H1 inline style HSL bug)** - **`theme.ts` + `Hero.tsx` root cause**. `theme.config.json` stores `"hero-h1": "0 0% 100%"` (raw HSL components). `getThemeConfig().colors` returns this raw string. `Hero.tsx` applies it directly via `style: { color: h1Color }`, producing invalid CSS `color: 0 0% 100%`. For semantic keys, the theme system uses CSS variables with `hsl(var(--x))`, but `hero-h1` is a non-semantic key (not in `SEMANTIC_KEYS` set in `theme.ts` line 34-39), so it gets emitted as `--color-hero-h1`.

- **Fix in `Hero.tsx`**: Wrap the color value in `hsl()` when it looks like HSL components: `const resolvedColor = h1Color && !h1Color.startsWith('#') && !h1Color.startsWith('hsl') && !h1Color.startsWith('rgb') ? \`hsl(\${h1Color})\` : h1Color;`

**Task 14 (robots.txt hardcoded domain)** - **`public/robots.txt` root cause**. The file is a static file with `Sitemap: https://stadtkueken.de/sitemap-index.xml` hardcoded. Similarly, `generate-sitemap-from-dist.mjs` defaults to `stadtkueken.de` (line 26).

- **Fix**: Make `robots.txt` dynamically generated at build time (or via the sitemap script). The sitemap script already reads `SITE_URL` from env. Add a step that also rewrites `robots.txt` during build to use the correct `SITE_URL`.

### GROUP C: Component Root Cause (fix in `src/components/`)

**Task 7 (Empty bookingUrl CTA)** - **`Contact.tsx` + script root cause**. `Contact.tsx` always renders the booking button with `href={bookingUrl}` even when `bookingUrl` is `""`. The script doesn't set a fallback.

- **Fix (two-part)**:
  1. **In `Contact.tsx`**: Add a guard -- if `bookingUrl` is empty, use the first hero button's link as fallback (available from `pageData.hero.buttons[0]?.link`). If that is also empty, hide the button entirely.
  2. **In `06-generate-website.ts`**: In the "info + contact" chunk guidelines, add: "If business.bookingUrl is empty, use the first hero button link or a tel: link as the CTA href."

**Task 11 (Subpage titles don't use metadata.title)** - **Astro page template root cause**. `impressum.astro` (line 34), `datenschutz.astro` (line 33), `ueber-uns.astro` (line 38) all use `title={\`\${pageData.business.name} - \${pageTitle}\`}`instead of`title={pageData.metadata.title}`.

- **Fix**: Change the `title` prop in all three templates to `title={pageData.metadata.title}`.

**Task 23 (Footer social icon invisible)** - **`Footer.tsx` root cause**. Social icons use `bg-primary` on a `bg-primary` footer background (line 224).

- **Fix**: Change `bg-primary` to `bg-white/20` or `bg-primary-foreground/10` in `Footer.tsx`.

**Task 24 (noindex for legal pages)** - **Astro page template root cause**. `impressum.astro` and `datenschutz.astro` don't pass `noIndex={true}` to the layout. `BaseLayout.astro` already supports `{noIndex && <meta name="robots" content="noindex, nofollow" />}`.

- **Fix**: Add `noIndex={true}` prop to `BaseLayout` in both `impressum.astro` and `datenschutz.astro`.

**Task 25 (FAQ SSR rendering)** - **Astro island root cause**. The FAQ component renders via a React client island. Need to check how it's included.

- **Fix**: Ensure FAQ content is server-rendered in the initial HTML, or provide a static HTML fallback.

**Task 26 (FAQ glob mismatch)** - **`index.astro` root cause**. The glob pattern `/src/data/current/**/*-home-faq.json` requires FAQ files to end with `-home-faq.json`. But `faqDataFile` in the data may not match this pattern.

- **Fix**: Either broaden the glob to also match `faq.json` patterns, or ensure the generation script names FAQ files consistently.

**Task 27 (Missing image width/height)** - **Component root cause**. `Gallery.tsx`, `Info.tsx`, `Header.tsx` render `<img>` without `width`/`height`.

- **Fix**: Add `width`/`height` attributes to `<img>` tags in each component.

**Task 28 (Info image fixed height)** - **`Info.tsx` root cause**. Fixed `h-64` class.

- **Fix**: Change to `h-64 md:h-80 lg:h-96`.

**Task 29 (Trust logos no lazy loading)** - **`TrustBlock.tsx` root cause**. No `loading="lazy"` on logo images.

- **Fix**: Add `loading="lazy"` to trust logo `<img>` tags.

**Task 30 (console.log in Map.tsx)** - **`Map.tsx` root cause**.

- **Fix**: Remove the `console.log` at line 40.

**Task 31 (target=\_blank on mailto)** - **`Header.tsx` root cause**. All header button links get `target="_blank"`.

- **Fix**: Conditionally omit `target="_blank"` when `href` starts with `mailto:` or `tel:`.

**Task 32 (Gallery/Reviews bg collision)** - **`GoogleReviews.tsx` root cause**.

- **Fix**: Change `bg-muted` to `bg-white` in `GoogleReviews.tsx`.

**Task 33 (Logo link to /)** - **`Header.tsx` root cause**. Logo href is hardcoded to `/`.

- **Fix**: Change to `/${lang}` or `/de` dynamically.

**Task 35 (Hero CTA spacing)** - **`Hero.tsx` root cause**. `mt-12` on line 172.

- **Fix**: Change to `mt-6 sm:mt-12`.

### GROUP D: Data-Only Fixes (fix in `websites.json`)

**Task 4 (Wrong location data for eisdiele-suedstadt)** - **Data root cause**. The generation script/AI populated Linden data for Sudstadt. This is a one-time data correction.

- **Fix**: Manually correct `business.location.district`, `business.location.neighborhood`, and `business.brandName` in the eisdiele-suedstadt entry.

**Task 5 (Wrong brandName for eisdiele-list)** - **Same as Task 4** -- AI reused Linden data.

- **Fix**: Correct `business.brandName` for eisdiele-list.

**Task 6 (Address conflict on eisdiele-suedstadt)** - **Data root cause**. Conflicting addresses in different sections.

- **Fix**: Determine the correct Sudstadt address and update all references.

**Task 10 (Missing IceCreamShop schema)** - **Data/script root cause**. The template and script don't include LocalBusiness/IceCreamShop schema generation.

- **Fix**: Add IceCreamShop schema to the template and generation script guidelines.

**Task 19 (Incomplete Organization schema)** - **Data root cause**. AI didn't fill telephone, PostalAddress @type, ContactPoint @type correctly.

- **Fix**: Data correction + improve schema chunk guidelines in the generation script.

**Task 20 (WCAG contrast failures)** - **Theme config root cause**.

- **Fix**: Adjust color values in `theme.config.json`.
